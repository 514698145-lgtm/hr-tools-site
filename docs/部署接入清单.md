## 接入顺序

1. 用户完成 GitHub 登录，确认目标仓库及可见性。先检查已有文件和默认分支，不能覆盖旧仓库内容。上传前核对待提交文件。
2. 运行 GitHub 构建；在 Pages CMS 官方应用中仅授权目标仓库。用户完成需要其确认的安装授权。验证一次草稿编辑与构建，草稿不能进入公开产物。
3. 用户确定域名、云地域和预算。中国内地区域的域名备案及 CDN 接入条件需要购买前核实。OSS域名不能替代正式HTML访问域名。
4. 静态网站采用 OSS + CDN；/api/* 另接持久化后端。建议小规模先用单实例服务并备份，后端选型与费用待用户确认。不能丢弃反馈、管理回复和排行榜功能。
5. 通过 GitHub Environment/Secrets 配置最小权限部署凭据，不通过聊天发送密码/AccessKey，不将凭据写入仓库。生产环境加入发布审批。
6. 发布流程需补齐：检查→生产构建→备份/版本管理→只上传dist→刷新CDN→公网验收。当前仅有构建检查，不声称已接入OSS。
7. 验证 HTTPS、目录 index.html、真实404、表单链接、API不缓存、管理员登录限制、数据持久化和回滚后再启用搜索收录。随后处理301、Sitemap和站长平台提交。
