# 发布与恢复操作

2026-10-14。已完成候选发布包与隔离恢复工具；尚未完成OSS/CDN上传和公网回退。以下步骤不能代替实际生产验收。

## 静态候选包

```powershell
& .venv/Scripts/python.exe scripts/package_release.py --candidate
& .venv/Scripts/python.exe scripts/package_release.py --verify outputs/releases/<实际包名>.zip
```

打包时重新构建并运行全站静态检查。ZIP包含 `site/` 和 `release-manifest.json`，清单记录Git提交、工作区是否有未提交修改、构建模式、验收缺项、每个文件的SHA256、字节数、Content-Type与缓存策略。路径穿越、私有目录、隐藏文件、密码/运行数据、重复文件或校验不符均会被拒绝。站点构建不再复制 `.gitkeep` 等工作区占位文件。

不带 `--candidate` 时，必须通过全部生产门禁、使用生产域名并保持已提交的干净工作区。候选包始终标记 `purpose=candidate`，即使页面含正式域名，也不表示可自动发布。

当前资源名没有内容哈希，清单使用 `max-age=0, must-revalidate`；不能给旧文件名设置一年immutable缓存。实际OSS上传必须应用清单元数据，并在CDN侧明确刷新策略；仅生成清单不会改变云端缓存。

CI 的 `static-site-and-checks` 产物包含候选ZIP及检查报告。静态回退应使用上一份经过验收的包，核对文件后重新上传并刷新缓存；已删除页面要结合OSS版本和清单差异恢复或移除，不能把重新上传旧包等同完整回退。尚未实现/演练云端自动回退。

## 私有运行时备份

服务器 `hr-tools-backup.timer` 调用 `/usr/local/sbin/hr-tools-backup`。没有持久数据时跳过，不再无谓重启API；有数据时停单一写进程，快照 `feedback.json` 和 `game.json`，生成SHA256清单后恢复API并等待健康检查通过。失败时也尝试恢复原先运行的服务。

- 快照目录 `/var/backups/hr-tools` 权限0700；文件0600，不自动清理旧备份。
- 快照仅含两份运行数据及校验清单，不包含管理员密码；JSON格式错误或游戏数据缺少对应身份库时拒绝生成。
- 当前生产没有业务JSON数据，不能以定时任务返回成功证明真实业务备份已产生。
- 单机备份不能覆盖整机/磁盘丢失。异地私有备份尚未接通。

## 恢复到隔离目录

```text
python3 scripts/runtime_archive.py inspect /private/path/runtime-<时间>.tar.gz
python3 scripts/runtime_archive.py restore /private/path/runtime-<时间>.tar.gz /private/path/empty-staging
```

工具先验证整个归档，再向空目录写入允许的文件；拒绝覆盖已有数据、符号链接、路径穿越、重复成员、异常JSON或哈希不符。不直接覆盖 `/var/lib/hr-tools`。旧版无清单的归档可读取，但明确返回 `checksumsVerified=false`，不能声称历史内容已由SHA256核验。

管理员密码由服务器原有独立文件/环境配置保留，不能从备份恢复出另一份密码。生产恢复前应停API、额外快照当前数据，校验隔离恢复结果和权限，再由维护者按审核过的操作替换两份JSON，启动API并确认身份、反馈、未读、榜单和管理员重新登录。旧会话不跨进程恢复。当前工具只负责隔离恢复，尚未执行真实生产替换。
