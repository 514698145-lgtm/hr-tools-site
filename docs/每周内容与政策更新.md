# 每周内容与政策更新

2026-10-14 用户授权：每周检查全站内容，尤其政策及工具中使用的数字；核实变更后采用新规则，网站上线后继续执行。此授权覆盖例行无歧义更新，不取消首次上线资料确认、购买或新增权限确认。

## 运行安排

- 香港服务器每周一北京时间08:17运行 `hr-policy-watch.timer`。`Persistent=true` 使停机错过的定时在恢复后补跑，不保证停机期间即时执行。
- 当前聊天的每周一09:00复核任务（自动化ID `hr`）读取云端报告并完成官方检索、证据判断、代码/文章修订、测试及发布。聊天自动化目前依赖本地执行环境；云端抓取器独立运行，但不会自行理解法规或改数。电脑不可用时完整智能更新会延后，不能宣称已实现无人值守云端改稿。
- 上线前必须验收完整更新链路，并明确智能复核的常驻执行环境。`config/maintenance.json` 中 `endToEndPublicationVerified` 未通过时，发布检查阻断。不能将抓取成功或计时器启用当成自动更新已全部完成。

## 覆盖范围

`scripts/build_watch_manifest.py` 从 `content/`、`config/`、`public/data/`、`public/assets/` 和构建脚本形成文件清单，包含全部Word/Excel下载模板。自动提取站内引用URL及文件反向索引，记录Markdown核对日期和复核期限。来源域名标识只用于分流，`.gov.cn` 也不自动代表某条规则适用。

城市参数从现有计算模块的真实记录导出，保留城市、人员/医保类型、有效月份、字段值、来源及核验状态，不另造一套参数。50城分别有检索任务，监控现有官方导航入口中的政策链接。目录型网页变化仅是线索，不等于已核实新政策。

每周智能复核必须主动搜索，而不只读取旧URL：

1. 按50城及现有医保类型核查养老、失业、工伤、医疗、生育、公积金。关注缴费工资上下限、个人和单位费率、固定附加费、最低工资、公积金比例和取整、新旧人员差异、年度调整及临时减免到期。
2. 全国税务/财政和相关劳动法规：个税税率、累计预扣、奖金单独计税适用期限和次数、专项扣除、补偿计算边界。调薪预算、到手工资、用工成本、HR数据分母等也检查关联影响。
3. 所有资讯及政策知识库正文、FAQ、案例、来源和日期；无新证据不只刷新日期。历史真实案例明确历史背景，不改写成当期规则。
4. 64份工作表/表单、7份批量母版、官网导航、导览、企业服务链接、联系方式及免责声明。维护者才能确认的信息变化不得从搜索摘要臆断。
5. 来源打不开/验证码/403/证书错误/空正文记为失败，寻找公开权威替代来源；不能记作“无更新”，不绕过登录或验证。

## 证据到更新

每次新建 `docs/policy-reviews/YYYY-MM-DD.md`（仅公开证据与脱敏信息），列出：文号和官方URL、发布/生效/截止日、地域、险种、人员类型、变更前后数值、单位和取整、受影响源码/文章/模板、测试结果、Git提交、线上验收或阻塞。

证据清晰、适用对象和算法不变的例行数值更新可直接执行，不每项重复请用户批准。新公式、相互冲突的文件、无法确定适用对象或只有转载时保留待核验并通知用户。禁止网页数字抽取后直接覆盖计算参数。

- 在 `public/assets/city-policies.js` 增加有生效区间的记录，不覆盖历史月份；未来文件不提前应用，过期优惠不默认延长。
- 税率/补偿规则变更同步实际计算模块、配置口径与正文，增加生效日前后、上下限、类型差异和单条/批量一致性测试。
- 更新相关资讯、政策摘要、FAQ和唯一 `content/guide.md`；日期仅代表实际核验。
- 算法、字段或政策变动导致母版源哈希过期时，按既有模板生成流程重建；不单独篡改manifest来绕过模板验证。
- 再生成来源清单。CI会阻止新增内容或数值修改后没有同步清单的提交。

## 巡检状态与复核确认

服务器私有状态位于 `/var/lib/hr-policy-watch/`：`state.json` 保存上次成功指纹，`latest.json` / `latest.md` 是本轮报告，每轮另保留 `run-*.json`。网页只存规范化文本哈希、链接及来源，不保存账号/员工数据或全文。

状态区分 `baseline`（首次取得，尚未语义核验）、`unchanged`、`changed`、`failed`。待复核标志在后续页面没变或抓取失败时仍保留，不能被下一周覆盖消失。超过8天无新报告、服务失败及剩余35天左右到期的参数均须处理。

确认某条来源已复核后，向私有 `reviewed.json` 写入 `sources[URL] = {digest, reviewedAt, evidence}`，digest必须与实测内容对应，evidence指向具体审定记录；不批量自动消除待复核项。它不代替新通知检索。

抓取遇失败返回退出码2，systemd会显示失败并保留完整报告，复核任务必须读这些失败。无变化且无失败不打扰用户；实际更新、失效、漏跑或需要协助才通知。

## 发布与上线验收

使用现有GitHub → 静态构建 → OSS → CDN路径，绝不上传项目根目录或巡检私有状态。现有正式发布凭据/上传/HTTPS链路尚未接通时，只保存待发布变更，不能报告线上已经更新。

执行顺序：

1. 内容/计算/模板/来源清单检查，完整构建与相关桌面手机浏览器回归。
2. 生产门禁、旧版本备份、上传构建产物、刷新受影响HTML和政策资源。
3. 从正式HTTPS网址读取改后的正文、工具实际参数及单条/批量结果，验证缓存未保留旧版、旧月份仍正确。
4. 验证反馈和榜单未受静态更新影响；失败停止完成标记并恢复上一发布版本。
5. 保存证据及发布结果，最后才清除待更新项。搜索通知失败独立处理，不伪称已收录。

上线前一次演练须覆盖“候选变更→核验→参数/文章/模板→测试→OSS/CDN→公网检查”。没有真实政策变更时用隔离测试分支/临时测试目录，不向真实公开计算器放入假政策数值。通过后才标记 `endToEndPublicationVerified=true` 并启用生产自动更新开关。

## 维护命令

```powershell
& .venv/Scripts/python.exe scripts/build_watch_manifest.py
node --test tests/policy-watch.test.mjs
node scripts/policy-watch.mjs config/watch-manifest.json .local/policy-watch
```

云端：`systemctl list-timers hr-policy-watch.timer`；`systemctl status hr-policy-watch.service`；`journalctl -u hr-policy-watch.service`；私有报告由现有授权SSH读取。脚本无需阿里云AccessKey或新的模型密钥，抓取本身不增加新的付费资源。
