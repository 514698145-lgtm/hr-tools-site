# 模板重制与维护

本次按64个工作场景逐项检索样板，再原创重排结构，不复制商业模板文件、图像或品牌标识。来源索引见 `template-references.json`，原始候选见 `template-reference-search.json`。部分来源仅能读取搜索摘要；索引已标注访问限制，不把未打开的文件称为已核验成品。

26份表单采用Word，38份台账、清单和计算表采用Excel。各份的结构决策在 `scripts/template_designs.py`：面试评分采用量表和证据区；招聘申请采用需求性质、岗位要求和审批；调薪申请使用前后对照；员工沟通采用大段记录区；排班使用周矩阵；入离职及账号停用预置办理任务。

8份分析型Excel另有概览页：工资、渠道、预算、年假、合同、候选人、培训计划、资产归还。概览汇总所有预留行，不随筛选变化；0不能替代完整性核对。公式不自动推定法规待遇或资格。

## 维护流程

1. 先更新对应场景的参考来源和单份结构，不为统一外观删去业务必需内容。
2. Word由 `build_hr_documents.py` 生成，使用独立LibreOffice运行目录转换PDF并渲染检查；Excel由 `build_hr_workbooks.mjs` 使用artifact-tool生成、重算及渲染。
3. 检查每份Word的所有页面、每份Excel的每个工作表，修复孤立签字栏、截字、分页及公式问题。
4. `finish_hr_workbooks.py`发布静态文件、实际预览和8个混合格式ZIP合集；更新目录manifest。替换当前文件，不建立历史版本入口。
5. 运行文件结构检查、下载文件公式重算、页面下载和移动端检查。同一份 `content/guide.md` 同步替换。

模板文件及预览是已构建静态资产，未来GitHub构建和OSS部署无需安装Office，也不在用户浏览器生成文档。文章、工具说明和SEO继续沿用Pages CMS、Markdown和静态构建路线。

本次不部署，不创建GitHub仓库，不连接外部CMS或云服务。
