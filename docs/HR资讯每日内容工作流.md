# HR资讯每日两篇工作流

用户要求记录：2026-10-16。仅用于独立网站 www.hrtoolkit.cn 的HR资讯，不混入人力窝官网的业务事实、发布流程或工作日提醒。

## 时间和交付

每天按本对话自动任务当前设定时间执行，包含周末；目标为当日两篇原创SEO与GEO文章，每篇约1500字（建议1400—1800字，引用清单不计）。核验、排版和发布验收通过后，走现有Markdown → GitHub → 构建 → OSS → CDN链路发布。此为用户本次“每天更新两篇、放在HR资讯”的日更授权，不扩展到其他渠道。本文不擅自覆盖用户在任务界面调整的运行时间。

任务在本机当前对话运行，电脑、网络和Codex应用须保持可用。不会因此增加云端模型接口或购买资源；本机不可用时不能承诺准点写作。当天重复唤醒先查看已发布文章与当日记录，只补足当天两篇，不重复发布，不伪造漏跑日期。周更政策复核保持原任务，另一官网的提醒保持原样。

## 每次先搜索，再确定标题

1. 先看站内现有文章和最近30天选题记录，避免重复主题、关键词相互竞争或仅改地名年份。每天两个主题应有明显不同的HR工作问题。
2. 搜索最近24—72小时的HR热点：人社、医保、公积金、税务、劳动关系、招聘校招、薪酬福利、人才和用工数据，以及正规机构新发布的研究报告。没有足够消息时可扩到近7天、近30天仍在执行的重要变化；不把旧新闻改日期当热点。
3. 核对原文及至少一个独立权威来源。转载同一通稿不算独立验证。政策以发文机关原文为主，报告以出版方、研究机构、正式摘要/原文为主；核对版本、发布日期、统计期间、样本与口径。
4. 标题含真实热点名称或明确变化，配HR会搜索的核心问题和长尾词。日期不是所有标题的固定前缀；只有核实事件发生日才写“10月16日发布”等。不得以转载日期、搜索抓取日期冒充首发日期，不编搜索量。
5. 用户已提供第一资源公众号2026-10-16 18:27的出版介绍（https://mp.weixin.qq.com/s/XhWDK5riT3HTg0ChBR0_4w），浏览器已读全文，署中国劳动和社会保障科学研究院研究员侯增艳供稿。文中称2026版“近日”出版，10月16日是消息发布时间，不能推定图书当天出版。当前未取得全书及出版社独立2026书目，因此只能基于公开出版介绍作范围明确的解读，不拿2025版数字替代，不宣称已阅读全书。检索未命中也不能断言报告不存在。

## 每篇的内容要求

2026-10-18用户明确确认：每篇必须落实“开头直接回答问题、结论注明适用范围、引用可核验、有实际案例、有FAQ”。按《SEO-GEO内容生产标准.md》的五项必检要求逐项审校，在当日编辑记录中留下依据；缺少可靠来源或实际案例时换题或保留草稿，不用特殊“AI标签”替代内容质量。此要求纳入每日两篇的发布检查，不只作为可选写作建议。

沿用《SEO-GEO内容生产标准.md》：先回答HR的问题，再交代事实、适用范围和实际影响；观点与原文事实分开，使用自然具体的语言。至少包括：

开篇优先直接回答标题中的实际问题；重要结论附近写明对象、地区、期间及例外，避免摘取单段后失去适用边界。不套固定段落、不用关键词堆砌替代新增信息。长文目录和相关文章由构建自动生成，不在Markdown重复手工写一套。发布完成后检查Sitemap、robots和canonical；按用户2026-10-21最新要求停止主动URL推送，不运行任何--send命令。已登记的地图只更新文件，不每天重复登记；平台登记状态以《搜索收录与提交.md》核查为准，不混报可访问、已接收和真正收录/AI引用。

- 一个主关键词、3—5个自然长尾问题，记录公开搜索需求依据，不堆关键词。
- 原创标题、SEO标题、搜索描述、真实发布时间与实际修改日；只有一个H1，正文H2/H3层次清楚。
- 重要政策、数字和报告结论就近标明官方来源、日期及口径。至少两个可核验权威来源；若只有一份独家原始报告，相关事实无法独立验证时明确边界，不强凑第二个“证明”。正文用机构、资料名称、日期和文号引用，不做外链；完整URL存sources及审校记录。
- 一段有来源的真实正面实践，去除不必要的企业/个人识别信息。不使用负面曝光、处罚故事，不编效果数字，不把模拟测算包装成真实客户案例。没有合适案例则换题或留草稿，不能为凑满两篇编造。
- 3—5个有内容的FAQ，回答与正文一致。GEO按直接答案、清晰定义、可追溯引用和可复用段落落实，不声称有统一GEO认证或保证AI引用。
- 2—4个相关内链：优先对应工具、表格、政策知识页或已发布文章，锚文本说明用途；不每篇机械添加企业服务链接。发布前检查目标可达。HR资讯正文只做站内链接，禁止在图片或文字上添加外链。

## 分类和标签

仍用HR资讯现有集合，不另开栏目。行业报告、招聘热点归“最新资讯”；新规及政策实施归“相关政策”；具体工作方法归“HR实务”；解释本站操作才归“工具使用”。一篇一个分类、3—5个稳定标签，例如社保缴费、住房公积金、个税、薪酬福利、招聘、校招、劳动关系、人才发展、行业报告。标签用于聚合搜索，不用整句标题或每天新造标签。

## 配图

文章详情不放头图，保持标题、摘要直接进入正文。按主题在正文相关段落放1—2张图片，优先授权明确、与话题相关的摄影图片，必要时用原创信息图或AI示意；不强制每篇都做文字信息图。列表缩略图可复用正文图，不叠编号或重复标题。图片建议宽1200，压缩后本地托管，手机能读清。

网图必须逐图核验授权、摄影作者和使用限制，留来源与许可记录；不能将搜索到的图片直接当作免费素材。优先下载经核验允许商用的图片，不需要为了“避版权”再AI重构。AI重构本身不能消除版权风险；若使用AI，按图像技能与既有模型要求执行。示意图片不得当作真实活动现场或报告原图。数据图需有明确来源、单位和统计期，不造趋势。

cover/coverAlt只用于列表缩略图，shareImage用于分享/搜索；文章顶部始终不展示。正文使用Markdown图片，保留真实alt；紧接的斜体图注段会转为居中浅灰小字figcaption，没有独立图注则以图片alt为说明。图注写摄影署名、示意及必要来源，不放外链。避免图片承担唯一事实文字；关键结论保留可检索正文。

## 文章编号与兼容

固定slug和文件名为articleN，新文章从当前已用最高编号继续，检查已有草稿、迁移映射与历史审校记录，避免复用。编号以现有文件及审校记录为准，不把本文举例当作固定计数；不因改标题或排序重排编号。迁移旧地址需同步config/article-redirects.json，保留静态自动跳转与新canonical，更新内链及Sitemap。当前采用静态站点兼容跳转，不称为HTTP301；无需为例行新稿修改CDN或申请额外权限。

## 记录、验收和失败处理

每次记录到 docs/editorial-reviews/YYYY-MM-DD.md：检索时间、候选主题/去重结果、主词和长尾词、原文及交叉依据、事件日/统计期/生效日、公开案例事实与脱敏说明、图源/设计方式、内链、逐篇质检、Git提交、实际发布状态和链接。不得保存凭据、未脱敏案例或整份付费报告。

更新当前内容，重建watch-manifest并保持LF；检查草稿隔离、内容、图片及alt、移动排版、内链、分类/标签搜索、canonical、Article结构化数据和Sitemap，再使用现有门禁发布。正文和图片公网读取成功、部署完成标记匹配提交后，才算已发布。来源或案例不足保留draft；连接、构建、授权、发布失败说明具体情况，不把本地完成说成上线。不因文章引用新政策而直接改计算器数值，计算规则仍走政策复核流程。

按实际结果交付两篇标题与正式链接；未达到两篇时明确缺口和原因，不用低质量内容凑数。不自动发送邮件、群消息或在其他网站发文，不购买图片、报告、广告或新云资源。
