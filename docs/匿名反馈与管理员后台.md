# 匿名反馈与管理员后台

2026-10-04。当前为本地可用实现，未部署。

## 使用入口

- 各工具及资源模块底部：发布、分类、点赞、评论、定向回复、举报。
- `/feedback/`：昵称、匿名编号、自己发布/参与的讨论、站内回复与状态提醒。桌面顶部及工作台提供入口。
- `/admin/feedback/`：密码登录；按模块/状态/可见性/举报/关键词筛选；官方回复、定向回复评论、更新状态、隐藏或恢复吐槽/评论、处理举报、退出登录。
- `/admin/`：网站管理总入口。Pages CMS仍只负责文章与公开内容，不管理互动记录。

## 身份和提醒

匿名身份由服务端生成。浏览器仅以HttpOnly、SameSite=Strict Cookie持有随机凭据；数据文件仅保存凭据摘要。公开昵称与随机编号不是凭据，不能用于恢复身份。Cookie有效期一年；清除网站数据、换设备或Cookie失效后不能自动找回。此阶段没有恢复码、账户同步、邮件或系统推送。

2026-10-22调整：新身份使用随机趣味前缀和公开编号尾号生成不同昵称，服务端写队列内核对不重名；昵称持久保存，不因刷新变化。旧身份仅替换共用的“认真工作的HR”默认名，不变更凭据、编号、反馈或游戏历史；用户已自选的名字保留。自选重名在同一写队列内拒绝，改名后通过现有游戏事件通知刷新排行榜，不需重新打分。

点赞按匿名身份去重，可取消，重复请求不累计。不能保证一人只有一个身份；匿名创建、发布、评论及其他交互都有基本频率限制。昵称禁止含官方身份称呼；官方标识由受保护的管理员接口决定，不能由评论提交字段指定。

评论和状态更新通知发起人及可见评论的参与者，排除发起动作的匿名用户自己。本人只能读取/标记自己的提醒。只在访问或切回网站时更新顶部未读数；不持续后台轮询。最多保留每人最近100条提醒。隐藏吐槽或评论对应的提醒不公开展示；恢复后可重新显示。

## 本地存储与兼容

`scripts/feedback-api.mjs` 由 `scripts/serve.mjs` 提供API。数据在 `.local/feedback.json`，禁止放进public/dist/Git。原数组格式在读取时兼容转换，原留言保留为早期匿名用户、原回复保留为官方回复；不擅自把无身份旧留言分配给新用户。下一次成功写操作原子保存新格式。

本地使用单进程队列和原子文件替换，不能直接用于多实例云服务。管理员密码来自运行环境或本地私有文件，登录会话8小时、服务重启后需重新登录。匿名身份摘要及提醒持久化，重启不丢失。测试在独立临时目录进行，不往真实反馈库灌入样例。

## OSS/CDN上线衔接

静态页面按既定Pages CMS→Markdown→GitHub→构建→OSS→CDN发布。`/api/*`另由受保护的服务提供，并将文件存储换成数据库事务；前端采用同源路径，CDN需把API转发到独立服务且禁止缓存API响应。

正式服务配置 `HR_PUBLIC_ORIGIN` 为正式HTTPS来源，Cookie加Secure；另行配置管理员密钥、持久数据库、限流、日志及备份，不能把本地文件服务直接作为多实例部署。用户页面无需登录；管理员认证始终独立。私有提醒页面与管理页面不进入Sitemap、不允许收录。
