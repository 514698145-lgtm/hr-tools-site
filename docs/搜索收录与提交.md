# 搜索收录与提交

## 当前状态与站点优先级

2026-10-21：官网优先站点由用户明确为 https://www.wowoohr.com/；本站 https://www.hrtoolkit.cn/ 为次优先站点。两站分开验证、记录、提交，不向官网的站点入口塞入工具站URL。不修改其他项目的代码或复制其私有资料。

- 本站 Sitemap：https://www.hrtoolkit.cn/sitemap.xml ，本日核查127个不重复公开网址，覆盖14篇资讯及列表第2页，与可索引SEO记录一致。数量随实际内容自动变化，不是固定配额。
- robots.txt 允许抓取并指向该Sitemap；后台、工作台、反馈、草稿、旧日期工具和兼容跳转页不纳入。规范网址为www的HTTPS地址。
- 站点地图随构建发布更新，更新文件不等于向搜索引擎发送提交请求；不为了限次而停止更新Sitemap。
- 今天此前IndexNow回执为HTTP200，仅表示接收，不表示收录、排名或AI引用。历史Actions回执保留30天。
- 百度、必应和Google账号内站点验证、实际配额和Sitemap提交记录仍需分别核查；meta、Sitemap可访问或IndexNow成功不代表账号接入完成。

## 配额判断

- 百度：官方说明配额根据站点质量等因素调整，站点之间可能不同。用户看到的10条先按该站点/该工具当前配额处理，不认定为账号全部网站合计10条，也不推定每个网站都有10条。同站点不同提交方式是否共用，以当前控制台和对应工具说明为准。额度不能跨域名挪用；若另有账号共享限制，先留给官网，余额才给本站。
- 必应：传统URL Submission API可用带siteUrl的GetUrlSubmissionQuota查询；实际日/月额度以返回为准。本站现有通道是IndexNow，有自己的站点限流和返回状态，不和传统接口或百度额度混算，也不宣称无限配额。
- Google：Sitemap、网址检查中的请求索引、Search Console API和Indexing API是不同能力，不能混算“每日10条”。普通资讯和计算工具采用Sitemap发现；必要时才手工请求索引，官网优先。Indexing API仅支持符合要求的职位发布或直播页面，不能用来批推普通HR资讯。

## 每日一次的执行

1. 以北京时间自然日为准，各引擎每天集中处理一次；只选新发布或有实质修改的公开规范URL，无变化不提交。共享额度先官网；独立站点额度各用各的，官网剩余额度不能借给本站。不使用多账号或变换域名绕限。
2. 原GitHub发布工作流只负责构建、上传、CDN刷新与公网核验，已移除每次发布自动通知步骤。每日现有HR资讯任务在实际发布完成后运行：

   `.venv/Scripts/python.exe scripts/daily_search.py --send --report reports/search-notifications/YYYY-MM-DD.json`

3. 命令目前只接通本站IndexNow，不代称百度、Google或官网账号流程已接通；去掉`--send`只读校验。不新增付费服务或云权限。
4. 私有状态`.local/search-notifications/state.json`保存最近一次接收的公开manifest、北京时间最后尝试日期及回执。首次使用今天真实接收回执及对应线上manifest初始化；状态缺失禁止全量重推，先恢复/核验。不能以当前manifest冒充全部已通知。
5. 对比最后一次已接收版本与当前完整正式版本，汇总期间多次部署的变化，避免只比最后两次部署而漏稿。页面须在当前Sitemap中、哈希一致、允许索引；部署不完整或版本切换时停止。
6. 并发锁防止同机同时发送；请求前持久化当日尝试日期。响应不明、失败或429不在当天自动重试，未接收变化留到次日。200/202均留回执，202记录待验证，不靠重复推送促成验证。进程异常留下锁时先人工核查，不能自动清锁重发。状态只在本机，同站点不另建发送器。
7. 每日任务依赖本机、网络与Codex运行，不是服务器独立定时服务。若当天文章已完成，重复唤醒不再发稿；仍可检查当日回执与限次状态。有真实失败/待授权才报告，不用成功接收冒充收录。
